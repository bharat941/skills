## Proposed skill update

Add a **rendered-parity residual check** to the migration validation reference so that a
migration is only marked complete when its *rendered output* matches the baseline — not just when
its structural conversions pass:

1. After the structural conversions pass, diff the rendered baseline vs migrated HTML for the
   migrated pages and compute a parity score.
2. When parity falls below the gate (0.90) despite all conversions passing, emit a
   `residual-divergence` finding that lists the diverging text/style regions, so the engineer
   knows the migration is structurally correct but visually incomplete.
3. Document the common residual causes this comparison surfaced (dropped RTE styling, reworded
   content, responsive-image rendition differences) in the skill's reference so future migrations
   pre-empt them.

  cover, not in the rules themselves.
